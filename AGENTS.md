# Рабочий процесс

По прямому указанию пользователя от 16 октября 2026 года после каждой завершённой и проверенной итерации правок:

1. Зафиксировать изменения локальным Git-коммитом.
2. Опубликовать их в GitHub (`origin`, ветка `main`), предварительно проверив удалённое состояние. Не использовать force push и не перезаписывать чужие изменения.
3. Обновить сервер штатным `git pull --ff-only origin main`, затем пересобрать и обновить затронутый сервис. Для изменений веб-приложения — только `app` через Docker Compose, без перезапуска соседних сервисов.
4. Проверить readiness, обслуживаемые статические файлы и состояние контейнеров. Сообщить пользователю фактический результат публикации.

Это постоянное разрешение на указанный цикл; повторно спрашивать о коммите, push в main и штатном обновлении сервера не требуется. При конфликте, неожиданном состоянии или блокировке проверки не обходить ограничение, а сообщить причину.

Текущий сервер проекта: `root@31.25.237.195`, каталог `/root/FinancialAssistant`. Перед публикацией проверить чистоту рабочего дерева сервера и сохранить предыдущий образ приложения для отката. Не включать секреты и `.env` в коммиты или вывод инструментов.
