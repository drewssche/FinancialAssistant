# Личные финансовые отчёты

Серверная рассылка PNG в личный Telegram и HTML-письмом со встроенным изображением
и текстовой версией. Использует существующий SMTP, но отдельного явно настроенного
получателя. Данные выбираются только для одобренного профиля, которому принадлежит
`FINANCIAL_REPORTS_TELEGRAM_ID`. В групповые чаты отчёт не отправляется.

## Расписание и периоды

09:00 Europe/Minsk (проверка каждые 15 минут, точность таймера 10 секунд):

- понедельник: предыдущие понедельник–воскресенье;
- 1-е число: предыдущий полный календарный месяц;
- 1 января: предыдущий полный календарный год.

Один выбор на дату: год > месяц > неделя. При совпадении внутри старшего отчёта
есть краткий итог декабря/прошлой недели; отдельных сообщений не будет.
При восстановлении после простоя отправляется только последний причитающийся
отчёт за последние семь дней, без очереди старых сообщений. Дата включения
ограничивает этот поиск: отчёты до неё не отправляются.

## Содержание

Пришло, ушло и разница совпадают с аналитикой приложения: исторические операции,
движения по долгам и валюте. Это результат периода, не банковский остаток.
Макет выбирается автоматически по периоду:

- **Экспресс — неделя:** крупная разница, полосы прихода/оттока, три основные
  категории с иконками, изменение оттока к предыдущей неделе.
- **Кольцо — месяц:** приход/отток, кольцо расходов по операциям (пять категорий
  и остаток), итоговая разница. Расходы в кольце не смешиваются с движениями долгов.
- **Пульс — год:** разница, приход/отток, положительные и отрицательные результаты
  по месяцам в едином масштабе, три основные категории с иконками.

Во всех макетах — ближайший план на 7 дней с названием, направлением, датой и
суммой в исходной валюте; число остальных ближайших и неподтверждённых планов.
Краткие итоги совпавших периодов остаются внутри одного изображения. Полные
названия, сокращённые на картинке, сохраняются в текстовой версии письма.
Название плана берётся из источника и позиций, затем из комментария; отсутствие
названия обозначается явно. Прошедший неподтверждённый план не называется долгом.
Финансовые записи не меняются.

Генерация работает офлайн на Pillow и локальных масках иконок Lucide
(`app/assets/report_icons`, лицензии рядом), без браузера и сетевых запросов.
PNG одинаков для Telegram и почты; в письме он отображается шириной до 480 px.
При обновлении оформления уже сохранённые снимки и картинки не пересоздаются:
восстановившийся канал получает тот же отчёт, что ранее получил другой канал.

## Управление в приложении

Вкладка **Настройки → Отчёты** позволяет приостановить/включить рассылку, выбрать
недельные, месячные и годовые отчёты, каналы Telegram/почта и время отправки по Минску
(шаг 15 минут). Показываются настроенная почта и ближайшая будущая отправка. Получателей
через этот экран менять нельзя. Для неподключённого профиля данные получателей скрыты.
Изменения вступают в силу после «Сохранить рассылку» и сохраняются в `user_preferences`.
Обычное сохранение прочих настроек не перезаписывает эти параметры старым снимком.

При совпадении дат приоритет применяется только к включённым периодам. Отключённый
канал не получает отчёт; повторное включение не пересылает уже доставленные отчёты.
При возобновлении сохраняется ограниченное наверстывание последней пропущенной даты
за 7 дней. Время 09:00 является начальным значением, затем используется выбранное время.
Если настройки меняют во время построения изображения, перед отправкой они проверяются
ещё раз. Уже начатую сетевую отправку отменить невозможно.

## Настройка

В серверном `.env` (вне Git):

```
FINANCIAL_REPORTS_ENABLED=true
FINANCIAL_REPORTS_TELEGRAM_ID=<личный Telegram ID владельца>
FINANCIAL_REPORTS_EMAIL=<почта владельца>
FINANCIAL_REPORTS_START_DATE=<YYYY-MM-DD, день включения>
```

`FINANCIAL_REPORTS_STATE_DIR` по умолчанию
`/var/log/financialassistant/reports`, внутри постоянного тома `security_logs`.
Секреты SMTP и Telegram используются из существующих настроек, в логи не выводятся.
Пересоздать только `app`, чтобы он получил настройки. Затем установить штатные unit-файлы:

```
install -m 644 deploy/systemd/financialassistant-reports.service /etc/systemd/system/
install -m 644 deploy/systemd/financialassistant-reports.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now financialassistant-reports.timer
```

Проверка без отправки до 09:00: `docker compose exec -T app python -m scripts.run_financial_reports`.
После наступления срока эта команда является реальной отправкой, а не dry run.
Состояние таймера: `systemctl status financialassistant-reports.timer`.
Журнал: `journalctl -u financialassistant-reports.service`.
Остановка: `systemctl disable --now financialassistant-reports.timer`.
Отключение `FINANCIAL_REPORTS_ENABLED` с пересозданием app также запрещает отправку.

## Доставка и защита от дублей

Одна картинка и одно письмо на дату отчёта. SQLite-журнал фиксирует канал отдельно;
межпроцессный flock исключает конкурирующие запуски. Успешно отправленный канал
не повторяется при сбое другого. Снимок данных и изображение сохраняются и одинаковы
для обоих каналов, даже если второй канал восстановился позже.

Перед сетевой отправкой состояние `sending` фиксируется на диске. Сбой/таймаут после
начала отправки, включая прерывание процесса, переводится в `uncertain` и **не повторяется
автоматически**: SMTP и Telegram не поддерживают общий idempotency key. Это сознательный
выбор против дублей; неопределённая доставка требует проверки человеком. Отказы
предварительной проверки до отправки можно повторить следующим запуском. Записи
`sent` означают подтверждение Bot API / принятие SMTP, а не прочтение письма.

Файлы отчётов и журнал содержат личные данные, каталог закрыт правами 0700, файлы 0600.
Не удалять журнал при обновлениях. При полном восстановлении сервера восстанавливать
и каталог `reports` из постоянного тома; иначе защита от повторов старой установки
не сохраняется. Не сбрасывать состояния `sent/uncertain` ради автоматического повтора.
